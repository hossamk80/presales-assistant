# محلل متطلبات الأعمال الذكي / Smart Business Requirements Analyst

[![CI](https://github.com/hossamk80/presales-assistant/actions/workflows/ci.yml/badge.svg)](https://github.com/hossamk80/presales-assistant/actions/workflows/ci.yml)

تطبيق Streamlit ثنائي اللغة لتحليل كراسات الشروط الحكومية السعودية (اعتماد /
فرصة) وبناء العرض الفني: رفع المرفقات بكل صيغها، استخراج المتطلبات وجدول
الكميات، اقتراح هيكل العرض، الكتابة قسماً بقسم، مراجعة من لجنة وكلاء، ثم
التصدير إلى Word و PDF.

## هيكل المشروع المختصر

```text
presales_codex_ready/
├── README.md
└── business_analyst/
    ├── app.py                 # ملف التشغيل الرئيسي لتطبيق Streamlit
    ├── requirements.txt       # مكتبات Python المطلوبة
    ├── components/            # مكونات واجهة قابلة لإعادة الاستخدام
    ├── views/                 # شاشات التطبيق الداخلية
    ├── tests/                 # مجموعة الاختبارات التي يشغّلها CI
    └── utils/
        ├── ai_engine.py       # محرك Gemini: نص حر ومخرجات JSON مُهيكلة
        ├── db.py              # التخزين الدائم (SQLite): المنافسات والشركة والمعرفة
        ├── knowledge.py       # مستودع المعرفة: تقسيم وتضمين واسترجاع
        ├── document_blocks.py # تحويل Markdown المولَّد إلى كتل مستند
        ├── file_handler.py    # الاستخراج (مع OCR) وبناء Word و PDF
        ├── i18n.py            # نصوص الواجهة بالعربية والإنجليزية
        └── state.py           # حالة الجلسة وهيكل العرض
```

## سير العمل

0. **المنافسات** — أنشئ منافسة لكل عطاء. كل شيء بعدها يُحفظ تلقائياً على
   القرص ويُستأنف في أي جلسة لاحقة.
1. **التحليل والمخاطر** — رفع كل مرفقات المنافسة معاً (PDF/Word/Excel/CSV/HTML،
   مع OCR للممسوح ضوئياً) وتصنيف كل ملف: كراسة شروط · ملحق فني · جدول كميات.
   الدور مُرجَّح من اسم الملف وقابل للتعديل. ثم **دمج المرفقات** في سياق مشروع
   موحّد (الجهة، الموعد النهائي، التسليمات، القيود، الغرامات، الشهادات،
   متطلبات المحتوى المحلي)، يليه Go/No-Go ومصفوفة الأوزان والشروط الحاكمة.
2. **الامتثال وجدول الكميات** — استخراج آلي مُهيكل. **مصفوفة الامتثال** بثمانية
   حقول تربط كل متطلب باستراتيجية استجابة: المعرّف (REQ-001) · التصنيف
   (Technical / Operational / Administrative / Legal) · مرجع البند · المتطلب ·
   الأهمية (High / Medium / Low) · استراتيجية الاستجابة · الالتزام · الشهادة
   المطلوبة. **جدول الكميات** بتسعة حقول:
   رقم البند · التصنيف · البند · الوحدة · الوصف · المواصفات · كود البناء ·
   الكمية · **القائمة الإلزامية** للمحتوى المحلي.
   إعلان الالتزام وترشيح القائمة الإلزامية يبقيان قرارين بشريين لا يفترضهما
   النموذج — النموذج يقترح الاستراتيجية فقط.
3. **منشئ العرض الفني** — هيكل عرض يقترحه الذكاء الاصطناعي وفق **معايير اعتماد**،
   بعنوان مقترح وترتيب أقسام (`section_id`) وغرض ونقاط جوهرية لكل قسم، مبنياً
   على سياق المنافسة **ونطاق العمل من جدول الكميات** (البنود والمواصفات بلا
   كميات ولا أي رقم مالي). التسلسل مطلوب أن يبني الإقناع — من فهم الحاجة، إلى
   إثبات القدرة، إلى كيفية التنفيذ، إلى ضمان النتيجة — وكل قسم مربوط بمعيار
   تقييم أو شرط صريح.

   يتحقق النظام من الأقسام الإلزامية السبعة:

   | # | القسم |
   |---|---|
   | 1 | الملخص التنفيذي |
   | 2 | ملف الشركة والخبرات ذات الصلة |
   | 3 | المنهجية الفنية المقترحة وخطة التنفيذ |
   | 4 | الجدول الزمني ومعالم التسليم |
   | 5 | الهيكل التنظيمي والكوادر الرئيسية |
   | 6 | ضمان الجودة وإدارة مستويات الخدمة |
   | 7 | الالتزام بالمحتوى المحلي |

   الستة الأولى هي القياسية في معايير اعتماد؛ **المحتوى المحلي أُبقي إلزامياً
   سابعاً** لأن له وزناً تقييمياً في المنافسات السعودية. المنهجية والجدول الزمني
   **قسمان منفصلان** لأن لجان اعتماد تُقيّمهما بمعيارين مستقلين. والنظام
   **يحذّر إن أُدرج التسعير في العرض الفني** — الفني والمالي مظروفان منفصلان.
   الهيكل قابل لإعادة الترتيب والإضافة والحذف. ويجب أن تتضمن نقاط المنهجية
   **استراتيجية إدارة المخاطر** — عرض بلا معالجة للمخاطر يبدو غير واقعي أمام
   لجنة الفحص.
   ثم **كتابة قسماً بقسم**: لكل قسم حقل **توجيه الكتابة** يمرَّر إلى النموذج
   (مثال: «أبرز خبرتنا في القطاع الصحي»)، ويستند التوليد إلى ملف الشركة ومصفوفة
   الأوزان والشروط الحاكمة ومستودع المعرفة. و**المساعد الجانبي** يعمل بوضعين
   منفصلين على نفس الخانة:

   - **✨ نقّح** — يطبّق التعديل على نص القسم: أربعة إجراءات سريعة (أكثر إيجازاً ·
     أضف مؤشرات أداء · أبرز إدارة المخاطر · صياغة أرسمية) أو طلب حر، مع تراجع بنقرة.
   - **💬 اسأل** — يجيب عن سؤالك **دون المساس بالنص** («هل غطّينا شرط السعودة؟»).
     الجواب يظهر تحت المحرر ولا يُكتب في العرض، ويُحفظ آخر خمسة تبادلات للقسم.

   كلا الوضعين يعملان على سياق المنافسة كاملاً (الكراسة · السياق الموحّد ·
   مستودع المعرفة) لا على نص القسم وحده. وفشل الاستدعاء لا يمسح نص المستخدم.
4. **المراجعة والتسليم** — **لجنة من ثلاثة وكلاء** تراجع المسودة الكاملة قبل
   التقديم على اعتماد، لكل وكيل نطاقه:

   | الوكيل | يفحص |
   |---|---|
   | 🛠️ **الفني** | الجدوى الفنية · تغطية المنهجية · واقعية الجدول الزمني · قدرات الفريق · مستويات الخدمة |
   | 💰 **التجاري** | اتساق جدول الكميات · وضوح هيكل التسعير · مخاطر الكلفة · جدول الدفعات · حدود المسؤولية بين التوريد والتركيب والتشغيل · **عزل التسعير عن العرض الفني** |
   | ⚖️ **القانوني** | نظام المنافسات والمشتريات الحكومية · التزامات المحتوى المحلي والقائمة الإلزامية · الضمانات الثلاثة (ابتدائي · نهائي · كفالة المُورَّد) · تخفيف الغرامات التعاقدية |

   كل وكيل يُرجع **درجة جاهزية من 100** وتقييماً موجزاً و**نقاط قوة** و**ثغرات**
   و**توصيات عالية الأولوية**، والثغرات مربوطة بأقسامها فتُطبَّق على القسم بنقرة
   مع إمكانية التراجع. الوكلاء يعملون باستدعاءات منفصلة عمداً حتى لا يبرّر أحدهم
   ثغرة في نطاق زميله. **الجاهزية الإجمالية هي أضعف زاوية لا متوسطها** — زاوية
   واحدة ساقطة تكفي لرفض العرض، والمتوسط يخفي ذلك خلف زاويتين قويتين. دون 60
   يُعرض تحذير «غير جاهز للتسليم».
5. **التجميع والتصدير** — تُجمَّع الأقسام النهائية في ملف Word أو PDF باتجاه
   الكتابة الصحيح وبهوية الشركة: **غلاف** يحمل عنوان العرض و«مقدَّم إلى» الجهة
   المصدِرة (من دمج المرفقات) و«مقدَّم من» الشركة والتاريخ، ثم فهرس محتويات
   وترقيم صفحات. **لون العناوين وخط المستند** يُضبطان من ملف الشركة ويسريان على
   الغلاف والعناوين وترويسات الجداول في الصيغتين معاً. رفع قالب Word للشركة
   يُبقي هويته كما هي ولا تُفرض عليه ألواننا.

## الاختبارات والتحقق الآلي

كل دفعة إلى GitHub تشغّل CI تلقائياً — لا حاجة لتشغيل التطبيق محلياً للتأكد
من سلامته. يغطي CI أمرين:

1. **`test`** — 214 اختباراً على المنطق: تقسيم النصوص للتضمين، تحليل Markdown
   إلى كتل مستند، طبقة قاعدة البيانات، تحويل الاستخراج إلى جداول، ترقية جداول
   الكميات القديمة، بناء Word و PDF بالاتجاهين، اكتمال نصوص الواجهة باللغتين،
   ودقّة قوالب التعليمات، وتمرير توجيه الكتابة، وسلامة التنقيح عند فشل
   الاستدعاء، وتغطية كل وكيل لنطاقه، وحساب الجاهزية من أضعف زاوية، وبقاء
   الحقول القياسية عبر الدمج المجزّأ، وكتابة الخط في خانة النص المعقّد،
   وصمود الهوية أمام لون غير صالح. يعمل على Python 3.11 و 3.12.
2. **`boot`** — يشغّل الخادم فعلياً ويتحقق من استجابته، إضافةً إلى اختبار
   يقلع التطبيق كاملاً عبر `streamlit.testing` ويمرّ على كل صفحاته.

للتشغيل محلياً عند الحاجة:

```bash
cd presales_codex_ready/business_analyst
pip install pytest
python -m pytest tests/ -v
```

## التخزين والخصوصية

كل شيء يُحفظ في ملف SQLite واحد محلي: `presales_codex_ready/business_analyst/data/analyst.db`
(يمكن تغيير مساره بمتغيّر البيئة `ANALYST_DB_PATH`). لا يغادر أي من محتوى
العطاءات الجهاز إلا في استدعاءات Gemini نفسها. مفاتيح API تبقى في الذاكرة ولا
تُكتب على القرص ولا تُصدَّر مع المنافسات.

## مستودع المعرفة

ارفع السير الذاتية والشهادات وملفات المشاريع السابقة من **ملف الشركة**. تُقسَّم
وتُضمَّن بنموذج `gemini-embedding-001`، ويسترجع النظام منها ما يخص كل قسم أثناء
الصياغة فيستند العرض إلى خبرات الشركة الحقيقية بدل محتوى عام.

## القائمة الإلزامية للمحتوى المحلي

عمود **القائمة الإلزامية** في جدول الكميات ترشيح من النموذج لا حكم نهائي.
النموذج لا يملك القائمة الرسمية محفوظةً، فبدون مرجع يبقى الترشيح اجتهاداً.

لتحسين دقّته: ارفع القائمة الرسمية إلى **مستودع المعرفة** — يسترجعها النظام
تلقائياً ويحقنها في تعليمات الاستخراج فيصير الترشيح مبنياً على مرجع.

في كل الأحوال راجع العمود يدوياً قبل الاعتماد؛ الخطأ فيه له كلفة نظامية.

## الهوية البصرية للمستندات

من **ملف الشركة** يُضبط **لون العناوين** و**خط المستند**، ويسريان على غلاف Word
و PDF وعناوينهما وترويسات جداولهما — الصيغتان تُقدَّمان للجنة الفتح نفسها فلا
يصح اختلافهما.

ملاحظتان:

- الخط يجب أن يكون **مثبَّتاً على جهاز من يفتح الملف** وإلا استبدله Word بغيره؛
  الملف لا يحمل الخط بداخله.
- رفع **قالب Word للشركة** يُلغي فرض هويتنا — القالب يحمل هوية الشركة أصلاً.

The heading colour and document font are set in the company profile and apply
to the Word and PDF cover, headings and table headers alike.

## اللغة / Language

النظام ثنائي اللغة بالكامل. من **إعدادات النظام** يوجد إعدادان مستقلان:

| الإعداد | يتحكم بـ | الخيارات |
|---|---|---|
| **لغة الواجهة** | كل نص ظاهر في الواجهة واتجاه الصفحة | عربي · English · كليهما |
| **لغة المخرجات** | ما يولّده النموذج واتجاه Word و PDF | عربي · English · كليهما |

يمكن العمل بواجهة إنجليزية مع توليد عرض عربي والعكس.

نصوص الواجهة كلها في `utils/i18n.py`؛ أي نص جديد يجب أن يحمل `ar` و `en`
معاً — يحرس ذلك اختبار في CI.

The system is fully bilingual. Interface language and output language are set
independently; every UI string lives in `utils/i18n.py` with both `ar` and `en`,
enforced by a CI test.

## ما هو غير منفَّذ

- **تكامل منصة اعتماد** — يتطلب وصولاً رسمياً للواجهة البرمجية لا يملكه
  المشروع، والبديل العملي (تنزيل يدوي واحد لكل منافسة) في
  [`docs/etimad-integration.md`](docs/etimad-integration.md).
- **طبقة الذكاء السوقي** (المنافسون · العروض السابقة · حركة الأسعار) — بيانات
  تاريخية مجمّعة، منتج قائم بذاته لا نتيجة استدعاء واجهة.

المقارنة الكاملة مع المنصات التجارية في
[`docs/comparison-technicalproposal.md`](docs/comparison-technicalproposal.md).

## أوامر التشغيل من جذر المستودع

```bash
cd /workspace/presales-assistant/presales_codex_ready/business_analyst
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
streamlit run app.py --server.address 0.0.0.0 --server.port 8501 --server.headless true
```

بعد التشغيل افتح المتصفح على:

```text
http://localhost:8501
```

## إعدادات مهمة

- أدخل مفتاح Google Gemini API من صفحة **إعدادات النظام** داخل التطبيق، أو
  اضبط متغيّر البيئة `GEMINI_API_KEY` قبل التشغيل.
- موفر الذكاء الاصطناعي المفعّل حالياً هو Google Gemini عبر حزمة `google-genai` الموحّدة.
- النماذج المتاحة: Gemini 3.6 Flash (الافتراضي) · Gemini 3.1 Pro · Gemini 3.5 Flash-Lite.
- تُمرَّر كراسة الشروط كاملة ضمن نافذة السياق (مليون توكن)، ومع الكراسات الأكبر يتحول المحرك تلقائياً إلى تحليل مجزّأ ثم دمج.
- **النشر على خادم خارجي (Replit مثلاً) يُخرج بيانات العطاءات من جهازك** —
  اعتبارات الخصوصية في [`docs/deploy-replit.md`](docs/deploy-replit.md).
- حقول OpenAI وClaude موجودة كخيارات/حقول إعدادات فقط وليست موفرات مفعّلة حالياً.

### تصدير PDF بالعربية

يحتاج خطاً يدعم الحروف العربية على النظام. بدونه يرفض التصدير برسالة صريحة بدل
إخراج ملف بمربّعات فارغة:

```bash
sudo apt install fonts-dejavu fonts-hosny-amiri
```

### OCR للملفات الممسوحة ضوئياً (اختياري)

كثير من كراسات اعتماد ملفات PDF ممسوحة ضوئياً بلا طبقة نص. يكتشفها النظام تلقائياً،
ويشغّل OCR إذا توفّرت الأدوات، وإلا يعرض تحذيراً واضحاً بدل التحليل الناقص الصامت:

```bash
sudo apt install tesseract-ocr tesseract-ocr-ara poppler-utils
pip install pytesseract pdf2image
```
