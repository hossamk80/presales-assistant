## 1. الخلاصة التنفيذية

نظامنا يغطي بشكل معقول **قلب العملية**: رفع الكراسة → تحليل ذكي → بناء أقسام العرض → تصدير Word.
لكنه يغطي تقريباً **40٪** مما يعرضه الموقع المرجعي.

الفجوات الكبرى مرتّبة حسب الأثر:

|---|--------|-------|

| 2 | لا يوجد **ذكاء سوقي**: تحليل المنافسين، العروض السابقة، حركة الأسعار | عالٍ |
| 3 | لا توجد **مرحلة مراجعة** (فنية/تجارية/قانونية) قبل التسليم | عالٍ |
| 4 | **هيكل العرض ثابت** (9 أقسام مثبّتة في الكود) وليس مُقترحاً حسب طبيعة المنافسة | عالٍ |
| 5 | **اقتطاع السياق إلى 20,000 حرف** — يفقد معظم محتوى الكراسة الحقيقية | حرج تقنياً |
| 6 | لا يوجد **تصدير PDF**، ولا دعم **إنجليزي/ثنائي اللغة** | متوسط |

## 3. نقاط قوة نظامنا (لا يعرضها الموقع المرجعي)

1. **حقن القالب الرسمي للشركة** — رفع `.docx` بترويسة الشركة والحقن داخله (`company.py:78`).
2. **حلقة الإنسان في المسار (Human-in-the-loop)** — كل تحليل له حقل "ملخص معتمد" يحرّره المهندس، ويُمرَّر لاحقاً لتوليد المنهجية (`ui.py:61`، `doc_builder.py:117-121`). تصميم ذكي يمنع تراكم أخطاء الـ AI.
3. **تصدير/استيراد مساحة العمل JSON** مع استبعاد مفاتيح API (`settings.py:76-87`).
4. **تشغيل محلي بالكامل** — مفاتيح API في الذاكرة فقط، لا سحابة، مناسب للبيانات الحساسة.
5. **جداول امتثال وBOQ قابلة للتحرير** مع تصدير CSV.

## 6. قرار استراتيجي

النظام لن يجاري الموقع المرجعي في **بيانات السوق وتكامل اعتماد** بدون وصول رسمي لتلك البيانات، وهذا خارج نطاق التطوير البرمجي وحده.

التمايز الواقعي لنظامنا:
- **الخصوصية والتشغيل المحلي** — بيانات العطاءات لا تغادر جهاز الشركة.
- **حقن قالب الشركة الرسمي** — مخرَج جاهز بهوية الشركة، وليس مستنداً عاماً.
- **مستودع معرفة خاص بالشركة** — عرض مبني على مشاريع الشركة وسيرها الذاتية الحقيقية، لا محتوى عام.
- **الالتزام بمعايير اعتماد صراحةً** — الأقسام الإلزامية، وفصل الفني عن المالي،
  والمحتوى المحلي، والضمان الابتدائي: مفروضة في التعليمات ومفحوصة قبل التصدير.

بعد المراحل (أ) و(ب) و(ج) ثم 1 إلى 5، صار النظام مكتملاً في جوهر المنتج —
إعداد العرض الفني ومراجعته وتصديره — دون طبقة البيانات السوقية. الفجوتان
الباقيتان (تكامل اعتماد والذكاء السوقي) لا تُغلقان بالبرمجة وحدها.
